# 060-ops

- The harness is PROJECT-LOCAL: `.opencode/` in the workshop. opencode hot-reloads it on save.
  No install step. Never put harness files in `~/.config/opencode` (that applies them to every dir).
- opencode loads `.opencode/` from EVERY parent folder too: a checkout nested in another (a worktree) runs the
  PARENT's harness. Live tests of changed harness code run in a copy beside the repo (`~/Projects/<name>`).
- Permission rules are LAST-MATCH-WINS. List generic rules first, specific denies last.
  An agent's own `"*"` rule overrides every top-level rule. Hard stops go in `policies`.
- `**/X.md` does NOT match a root-level `X.md`. Always list both `X.md` and `**/X.md`.
- Saved "always allow" approvals override every `ask` for every agent in that project.
  Clear them with `opencode api permission.saved.list` / `permission.saved.remove`.
- Headless `opencode run` CANNOT answer "ask" permissions -> they auto-reject.
  Design agents so the happy path needs only allow-listed commands.
- Code Mode (`execute`) gives scripts an unhooked fetch(). Keep `execute` denied.
- Resolve paths from the plugin file or the session/project dir, never `process.cwd()`.
- `opencode run` takes its working dir from the $PWD env var, NOT the process cwd. A script that only sets cwd
  (Python `subprocess cwd=`) silently runs with no harness ("Agent not found"). Set PWD too, or `cd` first.
- "Read-only" allow-list entries can write or execute: `git diff/log --output=FILE`, `rg --pre CMD`, `find -exec`.
  They are denied in `policies`. Check flags, not just the command name, when allow-listing.
- opencode also reads Claude Code skills (`~/.claude/skills`, `~/.agents/skills`). Switch off with the service env
  `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1` (`opencode service set env ...` then `service restart`).
- Every AGENT shell runs in a macOS sandbox (`scripts/sandbox/`): writes only in its project (read-only with no project workdir; temp and caches too), never `.harness/`
  or anything under `.git` (no git add/commit: the human commits), never a doc file at the project root (BRIEF/BRAINSTORM/ARCHITECTURE/DESIGN/PLAN/REVIEW/CRITIQUE/BUGHUNT.md,
  any case: owners use the write tools; this Mac's sandbox matches paths without case anyway), no `.env`/keys.
  "Operation not permitted" = the sandbox. Scripts that write workshop state run from a human-typed command template
  (`` !`...` ``), never from an agent shell.
- Keep `mini-projects/` and every project folder a REAL directory, never a symlink: the doc-file deny in `agent.sb`
  matches the resolved path `/mini-projects/<proj>/<NAME>`, so a symlink there silently drops it.
- Plugin hooks name the delegation tool `subagent` (agent permissions still say `task:`). A turn = the ROOT session's
  `session.execution.started` ... `succeeded|failed|interrupted`; a child has its own pair; a message sent mid-turn
  joins the same turn. The plugin frees the chain lock at a root's turn end.
- That lock clean-up relies on `experimental.subagent_depth` staying 1 in opencode.json (JSON has no comments, so it
  is noted here): a child's delegation must never complete, or its own turn end could free the lock mid-chain.
- Headless `opencode run` can hang with empty output. Pass `--print-logs --log-level warn`.
- A `model:` line in an agent `.md` overrides `agent.<name>.model` in opencode.json. Agent files carry none.
- A kit agent (`permissions:` list) with a non-native frontmatter key such as `temperature` silently loses its
  whole permissions list. Bench `permission-lists-load` guards it.
- `$ARGUMENTS` is pasted raw into a command template BEFORE its `` !`...` `` shell runs. A slug is only as
  safe as the human's typing; never feed it untrusted text.
