# 060-ops

- opencode here runs as a BACKGROUND SERVICE. Changing `~/.config/opencode` config,
  agents, commands, skills or plugins does NOT apply until: `opencode service restart`.
  Symptom: your change "does nothing" and old behaviour keeps running.
- `harness/scripts/install.sh` syncs files and restarts the service for you.
- Headless `opencode run` CANNOT answer "ask" permissions -> they auto-reject.
  Design agents so the happy path needs only allow-listed commands.
- opencode server cwd can differ from session cwd (service runs from $HOME).
  Always resolve paths from the session/project dir, never `process.cwd()`.
- A smart model WILL look for a loophole in a prompt-only gate.
  Gates must be enforced in code (permission rules + safety-gate plugin).
- To move the harness to another machine: `bash harness/scripts/teleport.sh pack` on the old
  one, `unpack` + `install.sh` on the new one. Do NOT copy ~/.config/opencode (mixed state).
  Guide: TELEPORT.md.
